## EOA (Externally Owned Account / 外部所有アカウント)

Ethereum 系のブロックチェーンには、**アカウントが2種類しか存在しない**。

| 種類 | 正体 | 制御方法 | できること |
|---|---|---|---|
| **EOA** | 秘密鍵とペアになったアドレス | 秘密鍵による署名 | トランザクションを**発信**できる |
| **Contract Account** | デプロイされたコード | コードのロジック | 呼ばれたときにだけ動く。自分から発信できない |

「EOA」は前者を指す。要するに **人間（または開発者のスクリプト）が秘密鍵で操作する、普通のウォレットアドレス**のこと。「コントラクトアカウントではない方」という区別のために存在する用語。

### なぜこの区別が重要か

チェーン上のあらゆるトランザクションの起点は必ず EOA。コントラクトは自発的に動けないので、
誰か（EOA）が呼び出さないと何も起こらない。

コントラクトをデプロイする行為自体もトランザクションなので、
**デプロイには必ず EOA と、その EOA が持つガス代（ETH）が必要**になる。

### このハンズオンでの文脈

Step 0-4 で `cast wallet new` を実行して作るのが EOA。
「デプロイ用の秘密鍵を持ったアカウントを新しく作る」という意味。

### Coinbase Wallet との関係

Coinbase Wallet には2つのタイプがある。

| タイプ | 実体 | 秘密鍵のエクスポート |
|---|---|---|
| Coinbase Wallet（従来のセルフカストディ版） | EOA | 可能（シードフレーズあり） |
| Coinbase Smart Wallet（パスキー型） | **Contract Account**（ERC-4337 のスマートアカウント） | 不可 |

Smart Wallet の場合、そもそも Foundry に渡せる秘密鍵が存在しないためデプロイに使えない。
従来型であっても、**資産の入った鍵を開発ツールに渡すのは事故のもと**なので、
開発専用の EOA を別途作るのが正解。

## Chain ID

ネットワークを一意に識別する数値。署名対象に含まれるため、
あるチェーンで署名したトランザクションを別のチェーンで再生（リプレイ）できない仕組みになっている。

| ネットワーク | Chain ID |
|---|---|
| Ethereum mainnet | 1 |
| Ethereum Sepolia | 11155111 |
| Base mainnet | 8453 |
| Base Sepolia | 84532 |
| Anvil（ローカル） | 31337 |

## RPC (Remote Procedure Call)

ブロックチェーンのノードに問い合わせるための HTTP/WebSocket エンドポイント。
`eth_getBalance` や `eth_sendRawTransaction` といった JSON-RPC メソッドを叩く。

web3.py も `cast` も、内部でやっているのはこの RPC 呼び出し。
`https://sepolia.base.org` は誰でも使える公開エンドポイントだが、
レート制限があるため本番運用では Alchemy / QuickNode などの専用エンドポイントを使う。

---

## Gas / Gas 代

トランザクションの計算量に対して支払う手数料。ネイティブ通貨（Base では ETH）で支払う。
無限ループなどでネットワークを止められないようにするための仕組み。

Base は L2 なので Ethereum mainnet に比べてガス代が桁違いに安い。
Base Sepolia は testnet なので、faucet でもらった価値のない ETH で払う。

---

## L1 / L2

- **L1**: Ethereum mainnet そのもの。セキュリティは最高だが遅く高い
- **L2**: L1 にデータを書き戻しつつ、処理自体は別のチェーンで行う仕組み。Base は OP Stack ベースの L2

Base は L1（Ethereum）のセキュリティを継承しながら、手数料を大幅に下げている。
開発体験は EVM 互換なので L1 とほぼ同じ。

---

## Faucet

testnet の通貨を無料で配布するサービス。testnet の通貨に金銭的価値はないが、
ガス代の支払いには必要なので、開発の最初に取得する。

---

## ABI (Application Binary Interface)

コントラクトの関数シグネチャや引数の型を記述した JSON。
クライアント（web3.py）はこれを見て「どの関数をどう呼べばいいか」を知る。

`forge build` するとコンパイル成果物として `out/` 以下に自動生成される。
Python クライアントはこの ABI を読み込んでコントラクトを操作する。
